What is XGBoost?

XGBoost (Extreme Gradient Boosting) builds an ensemble of decision trees sequentially. Each new tree is trained to correct the residual errors of all previous trees combined. It is famous for winning Kaggle competitions and outperforming most other algorithms on structured/tabular data.

Why XGBoost is special

Uses a custom similarity score (not MSE) to split trees, plus built-in regularization (λ and γ) that prevents overfitting during tree building — not just after.

Key hyperparameters

λ (lambda) — L2 regularization on leaf weights
γ (gamma) — minimum gain required to split
η (eta) — learning rate (shrinkage)
max_depth — default 6

Part 1 — XGBoost for Regression

XGBoost builds special trees that use a unique scoring method — the similarity score — to decide how to split data. Everything begins with residuals.

Step-by-step algorithm

1
Make an initial prediction
Default is 0.5 for all observations (can be the mean too). Calculate residuals: Residual = Observed − Predicted
2
Put all residuals in one leaf
This becomes the root of your first XGBoost tree. Calculate the root's similarity score.
3
Try all possible splits — find the best Gain
For each candidate threshold, compute left and right similarity scores. Pick the split with the highest Gain.
4
Keep splitting until max_depth (default 6)
Recursively split each leaf node using the same Gain criterion.
5
Prune the tree using γ
Starting from the bottom, remove any branch where Gain − γ < 0. This is automatic regularization.
6
Calculate output value for each leaf
The leaf output is used (scaled by η) to update predictions.
7
Update predictions, recalculate residuals, repeat
New pred = Old pred + η × leaf output. Build next tree on new residuals.

The formulas

Similarity Score (Regression)

Similarity Score = (Σ residuals)² / (n residuals + λ)

λ (lambda) shrinks similarity scores → more pruning → prevents overfitting. With λ=0, no regularization.

Gain — how to evaluate a split

Gain = Similarity(Left) + Similarity(Right) − Similarity(Root)

Higher Gain = better split. Compare all candidate thresholds and pick the maximum.

Pruning condition

If Gain − γ < 0 → prune that branch

γ (gamma) = minimum Gain to keep a split. Larger γ = more pruning = simpler model.

Output Value (Regression leaf)

Output = Σ residuals / (n residuals + λ)

Note: same denominator as similarity score, but numerator is NOT squared here.

New Prediction

New Prediction = Previous Prediction + η × Output Value

η (eta) = learning rate. Default 0.3. Smaller η → more trees needed, but better generalization.

💡 StatQuest key insight: the Similarity Score measures how well residuals cluster together. When residuals "cancel out" (mix of positive and negative), the score is low. When they all have the same sign, the score is high.
⚠️ λ appears in BOTH the similarity score denominator AND the output value denominator — increasing λ makes both smaller, producing more pruning and smaller leaf outputs (shrinkage).

Part 2 — XGBoost for Classification

Classification uses the same tree-building machinery as regression, but with different formulas because outputs are probabilities, not continuous values.

What changes for classification

Residuals (different!)

Residual = Observed − Predicted Probability

Initial prediction = 0.5 probability. So initial residuals = 1 − 0.5 = 0.5 (for positive class) or 0 − 0.5 = −0.5 (for negative class).

Similarity Score (different!)

(Σ residuals)² / (Σ [prev_prob × (1−prev_prob)] + λ)

The denominator uses probabilities, not a simple count. This is the key formula difference.

Output Value (Classification leaf)

Output = Σ residuals / (Σ [prev_prob × (1−prev_prob)] + λ)

This is a log(odds) scale output — must be converted back to probability.

Converting output to a new prediction

log(odds)_new = log(odds)_prev + η × Output Value New Probability = e^log(odds)_new / (1 + e^log(odds)_new)

The logistic function converts the raw log(odds) into a probability between 0 and 1.

Cover — the classification-specific pruning guard

In classification, a leaf must have a minimum Cover value to be kept. Cover = denominator of similarity score − λ.

Cover = Σ [prev_prob × (1−prev_prob)]

If a leaf's Cover is less than min_child_weight (default = 1), that leaf is removed regardless of Gain. This prevents leaves with very few or very uncertain samples.

💡 In regression, Cover = number of residuals (always ≥ 1 by default). In classification, Cover can be < 1 if probabilities are near 0 or 1, causing pruning where a regression tree would not prune.

Part 3 — Mathematical Details

Part 3 derives the similarity score and output value formulas from first principles using the Taylor approximation and a general loss function. This is where the "why" behind the formulas is explained.

The objective function

Objective = Σ L(yᵢ, ŷᵢ) + Σ Ω(Tⱼ) L = loss function (e.g. MSE for regression, log-loss for classification) Ω = regularization = γT + ½λΣwⱼ² T = number of leaves, wⱼ = leaf output values

XGBoost minimizes this objective — it wants to reduce prediction error (loss) while penalizing complex trees (Ω). γ penalizes adding more leaves; λ penalizes large leaf weights.

Second-order Taylor approximation

To find the optimal leaf output, XGBoost approximates the loss function using its first and second derivatives around the current prediction:

L(yᵢ, ŷᵢ + f) ≈ L(yᵢ, ŷᵢ) + gᵢ·f + ½hᵢ·f² gᵢ = first derivative (gradient) = ∂L/∂ŷᵢ hᵢ = second derivative (hessian) = ∂²L/∂ŷᵢ²
💡 This is why XGBoost works for ANY differentiable loss function — the tree-building logic only needs the first and second derivatives (g and h) of whatever loss you choose. Swap the loss, swap g and h, same algorithm.

For regression (MSE loss)

L = ½(y − ŷ)² → g = ŷ − y = −residual → h = 1 → Similarity Score = (Σ gᵢ)² / (Σ hᵢ + λ) = (Σ residuals)² / (n + λ) ✓

For classification (log-loss)

g = predicted_prob − observed → h = prob × (1 − prob) → Similarity Score = (Σ gᵢ)² / (Σ hᵢ + λ) = (Σ residuals)² / (Σ p(1−p) + λ) ✓

Deriving the optimal output value

Taking the derivative of the approximated objective with respect to the leaf weight w and setting it to zero gives the closed-form optimal output:

w* = −Σ gᵢ / (Σ hᵢ + λ) Regression: w* = Σ residuals / (n + λ) Classification: w* = Σ residuals / (Σ p(1−p) + λ)

And substituting w* back gives the maximum similarity score (minimum loss for this leaf grouping):

Similarity Score = −½ × (Σ gᵢ)² / (Σ hᵢ + λ) (the −½ is often dropped as a constant)

General gain formula

Gain = ½ [ (Σ gL)²/(Σ hL + λ) + (Σ gR)²/(Σ hR + λ) − (Σ g)²/(Σ h + λ) ] − γ

XGBoost grows the tree as long as Gain > 0 (i.e., as long as splitting reduces the objective). γ directly enters the gain calculation — it's the regularization penalty for adding a split.

What λ controls

Adds to every denominator → shrinks similarity scores and leaf outputs → weight regularization. Makes individual observations less influential.

What γ controls

Penalizes number of leaves (T). Directly subtracted from Gain → a split must "earn" at least γ improvement to survive. Structure regularization.

⚠️ The Taylor approximation is only accurate when the step size (leaf output × η) is small. This is why the learning rate η (shrinkage) is important — it keeps updates small, keeping the approximation valid.

Part 4 — Crazy Cool Optimizations

When data is massive (millions of rows), the exact greedy split-finding algorithm is too slow. Part 4 covers the engineering tricks that make XGBoost production-fast.

1. Approximate Greedy Algorithm

Problem: Exact greedy tries every possible split value — O(n) per feature per node.
Solution: Instead of testing every value, propose candidate split points using quantiles of the feature distribution. By default, ~33 quantile buckets per feature. Evaluate only those candidates.

Exact: test all n split points Approximate: test ~33 quantile splits → ~33× fewer evaluations

Two modes: global (propose once per tree) or local (re-propose at each split). Local is more accurate but slower.

2. Weighted Quantile Sketch

Not all observations are equally important — some predictions are more uncertain than others. XGBoost weights each observation by its hessian (h = second derivative of loss).

Regression: h = 1 for all obs → equal weighting Classification: h = p(1−p) → uncertain observations (p≈0.5) get higher weight

Quantile buckets are built so that the total weight in each bucket is equal — not the count. This focuses more candidate splits where the model is most uncertain.

3. Sparsity-Aware Split Finding

Real data has missing values and zero-coded sparse features. XGBoost handles this with default directions:

For each split, XGBoost learns whether missing values should go LEFT or RIGHT. It tries both and picks the direction with higher Gain. This "default path" is then used for missing values at prediction time.

Result: 50× faster than naive approaches on sparse data (per the original paper).

4. Parallel Learning & Cache-Aware Access

Finding the best split across many features is parallelized: each CPU core evaluates different features simultaneously. Gradients (g) and hessians (h) are pre-fetched into CPU cache in contiguous memory blocks — avoiding slow random memory access during gain computation.

Core 1: evaluate splits for Feature A Core 2: evaluate splits for Feature B } simultaneously Core 3: evaluate splits for Feature C Then: compare all gains, pick the winner

5. Blocks for Out-of-Core Computation

When data doesn't fit in RAM, XGBoost divides it into compressed blocks stored on disk. Blocks are pre-sorted by feature values and can be decompressed in parallel. Disk I/O and CPU computation are interleaved so neither sits idle.
