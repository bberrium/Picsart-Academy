### Computer Vision Task-երի Համեմատություն

1. **Classification:** «Ի՞նչ կա այս նկարում»: Output-ը կլասների հավանականություններն են (Class Probabilities): Եթե վերջին layer-ը փոխենք, կարող ենք լուծել նաև Regression-ի խնդիր (օրինակ՝ տան նկարից կանխատեսել տան գինը):
2. **Localization:** «Որտե՞ղ է գտնվում **մեկ** հիմնական օբյեկտը»: Output-ը կլասն է + օբյեկտը սահմանափակող Bounding Box-ի 4 կոորդինատները՝ $(x, y, w, h)$:
3. **Object Detection:** «Որոն՞ք են և որտե՞ղ են գտնվում **ԲՈԼՈՐ** օբյեկտները»: Output-ը միաժամանակ բազմաթիվ Bounding Box-եր են և դրանց համապատասխան կլասները:

## 3. Sliding Windows («Մութ Ժամանակաշրջան» / The Dark Ages)

Նախքան Deep Learning-ի արդյունավետ ալգորիթմները, Object Detection-ը լուծվում էր Sliding Window մեթոդով:

```
+-----------------------------------------------------------+
|  Slide Window (Top-Left -> Bottom-Right)                  |
|  +-----------------------+                                |
|  | [Crop] -> CNN -> Cat? |                                |
|  +-----------------------+                                |
|                                                           |
|  Problem: Repeat 100,000s of times for different scales   |
+-----------------------------------------------------------+

```

### Մեխանիզմը

1. Վերցվում է կլասիֆիկացիայի համար վարժեցված CNN:
2. Նկարի վրայով շարժվում է փոքր պատուհան (window), կտրում է (crop) այդ հատվածը և փոխանցում CNN-ին:

### Խնդիրը (The Problem)

Օբյեկտներն ունեն տարբեր չափսեր և aspect ratio-ներ (օրինակ՝ մարդը ուղղահայաց ձգված ուղղանկյուն է, ավտոմեքենան՝ հորիզոնական): Բոլոր չափերի օբյեկտները գտնելու համար անհրաժեշտ է փորձարկել 100,000-ավոր տարբեր չափերի պատուհաններ նկարի յուրաքանչյուր հատվածում:

### Արդյունքը (Result)

Deep Neural Networks-ի համար սա հաշվողական տեսանկյունից **անհնար է** (Computationally Impossible): Անհրաժեշտ է Region proposals գտնելու ավելի խելացի եղանակ:

## 4. Selective Search Ալգորիթմը

100,000 կույր փորձերը փոխարինելու համար ստեղծվեց **Selective Search** ալգորիթմը (դասական Computer Vision մեթոդ): Այն միավորում է Exhaustive Search-ը և Image Segmentation-ը՝ գտնելով մոտ 2,000 հավանական տիրույթներ (Region Proposals):

```
+-------------------------------------------------------------------+
| Selective Search Flow:                                            |
| Input Image -> Over-segmentation -> Greedy Merging -> 2,000 Boxes |
+-------------------------------------------------------------------+

```

### Selective Search-ի Քայլերը:
![[Pasted image 20260804130123.png]]
1. **Step 1: Over-segmentation:** Նկարը սկզբում բաժանվում է հազարավոր փոքր, միատարր տիրույթների՝ ըստ pixel-ների ինտենսիվության (սովորաբար Felzenszwalb-ի ալգորիթմով):
2. **Step 2: Greedy Merging:** Հաշվարկվում է հարևան տիրույթների նմանության միավորը (Similarity Score): Ամենանման զույգերը միավորվում են:
3. **Step 3: Bounding Boxes:** Միավորման յուրաքանչյուր փուլում ստացված տիրույթի շուրջ գծվում է Bounding Box:
4. **Step 4: Repeat:** Պրոցեսը կրկնվում է հիերարխիկ ձևով (փոքրից մեծ), մինչև ամբողջ նկարը դառնում է մեկ տիրույթ:

### Նմանության 4 Մետրիկաները (Similarity Metrics):

1. **Color Similarity:** Արդյո՞ք տիրույթներն ունեն նույն գունային հիստոգրամը (օր.՝ կարմիր մեքենա գտնելու համար):
2. **Texture Similarity:** Համեմատում է gradient/edge-երը (օր.՝ ճյուղի վրա քամելեոն գտնելու համար):
3. **Size Similarity:** Խրախուսում է փոքր տիրույթների վաղ միավորումը, որպեսզի մեկ հսկայական տիրույթը չլանի ամբողջ նկարը:
4. **Fill / Shape Compatibility:** Ստուգում է, թե արդյոք A տիրույթը հարմար տեղավորվում է B տիրույթի դատարկությունների մեջ:

$$\text{Final Score} = w_1 \cdot S_{\text{color}} + w_2 \cdot S_{\text{texture}} + w_3 \cdot S_{\text{size}} + w_4 \cdot S_{\text{fill}}$$

## 5. Two-Stage Object Detection-ի Էվոլյուցիան (R-CNN Ընտանիք)

Two-stage ալգորիթմների էությունը.

1. **Stage 1:** Region proposals-ների ստացում (տիրույթների առաջարկում):
2. **Stage 2:** Այդ տիրույթների կլասիֆիկացում և Bounding box-երի ճշգրտում:

### 5.1 R-CNN (Region-based CNN)

![[Pasted image 20260804130217.png]]
#### Քայլերը:

1. **Step 1:** Selective Search-ով գտնվում է $\sim 2,000$ Region Proposal:
2. **Step 2:** Յուրաքանչյուր proposal կտրվում է (crop) և ձևափոխվում (warp/resize) ֆիքսված չափսի՝ $224 \times 224$:
3. **Step 3:** Բոլոր 2,000 նկարները **առանձին-առանձին** անցկացվում են CNN-ով (օրինակ՝ AlexNet) feature-ներ կորզելու համար:
4. **Step 4:** Կատարվում է կլասիֆիկացիա և Bounding Box-երի ճշգրտում (Regression):
![[Pasted image 20260804132349.png]]


```
[Input Image]
      │
      ▼
(Selective Search)  ──►  ~2,000 Candidate Regions
      │
      ▼
[Crop & Warp]       ──►  Ֆիքսված չափս (օր.՝ 227 × 227)
      │
      ▼
[ConvNet Pass]      ──►  4096-չափանի Feature Vector
      │
      ├───────────────────────────────┐
      ▼                               ▼
[SVM Classifiers]            [Bounding Box Regressor]
(Կլասի որոշում)               (4 Offset արժեքների կանխատեսում)
```

- **Առավելությունը:** R-CNN-ը առաջին արդյունավետ մոդելներից էր, որը համադրեց Convolutional Feature-ները Object Detection-ի հետ:
    
- **Թերությունը:** Ամեն նկարի համար 2,000 առանձին forward pass անելը CNN-ով հասցնում էր մշակման ժամանակը **$\sim 45$ վայրկյանի**, ինչը դրդեց **Fast R-CNN**-ի (RoI Pooling-ի կիրառմամբ) և **Faster R-CNN**-ի (RPN-ի կիրառմամբ) ստեղծմանը:

#### RoI (Region of Interest) Pooling Մեխանիզմը

* Selective Search-ի առաջարկած 2,000 Bounding Box-երը պրոյեկտվում են ստացված Feature Map-ի վրա:
* Քանի որ տարբեր box-եր ունեն տարբեր չափսեր (օր. $21 \times 14$ կամ $5 \times 9$), իսկ Dense layer-ներին անհրաժեշտ է ֆիքսված input, **RoI Pooling**-ը յուրաքանչյուր տիրույթ բաժանում է ֆիքսված $7 \times 7$ ցանցի (grid) և կիրառում **Max Pooling**:

```
+-------------------------------------------------------------+
| RoI Pooling Principle:                                      |
| Variable Region (e.g. 21x14) ---> Split to 7x7 Grid         |
|                               ---> Max Pool each cell       |
|                               ---> Fixed Tensor (7x7)       |
+-------------------------------------------------------------+

```

#### Արդյունքը և Նոր Խնդիրը (New Bottleneck)

* Արագությունը $45$ վայրկյանից իջավ **$\sim 2$ վայրկյան**:
* **Նոր խնդիրը:** $2$ վայրկյանից հիմնական ժամանակը ծախսվում է Selective Search-ի վրա, որն աշխատում է CPU-ի վրա: GPU-ն սպասում է CPU-ին:

---

### 5.3 Faster R-CNN: Զուտ Նեյրոնային Ցանցեր (Pure Neural Networks)

Faster R-CNN-ը լրիվ հրաժարվեց Selective Search ալգորիթմից:
![[Pasted image 20260804133031.png]]
#### Հիմնական Նորամուծությունը. Region Proposal Network (RPN)

* Selective Search-ի փոխարեն ավելացվեց երկրորդական նեյրոնային ցանց՝ **Region Proposal Network (RPN)**:
* RPN-ն օգտագործում է նույն Convolutional layer-ների Feature Map-ը, ինչ ցանցի մնացած մասը (կիսում են պարամետրերը):
* RPN-ն առաջարկում է Bounding Box-եր անմիջապես GPU-ի վրա:

#### Աշխատանքի Հոսքը (The Flow):

$$\text{Image} \rightarrow \text{CNN Feature Map} \rightarrow \text{RPN Proposes Boxes} \rightarrow \text{RoI Pooling} \rightarrow \text{Classifier \& Regressor}$$

#### Արդյունքը և Real-time Սահմանափակումը

* Արագությունը դարձավ **$\sim 0.2$ վայրկյան (5 FPS)**:
* Faster R-CNN-ը մինչ օրս համարվում է բարձր ճշտություն (High Accuracy) ապահովող ստանդարտ ալգորիթմ:

> **Real-time Video-ի խնդիրը:**
> Ստանդարտ տեսանյութերը ունեն $24$, $30$ կամ $60$ FPS (Frames Per Second): Faster R-CNN-ը ($5$ FPS) չի հասցնում աշխատել **Real-time** ուղիղ հեռարձակումների վրա: Այն վիդեոների վրա կիրառվում է միայն Post-processing տարբերակով:

## YOLO (You Only Look Once) 
## YOLO-ի Հեղափոխությունը և Պատմական Կոնտեքստը (2016)

2016 թվականին Object Detection-ի (օբյեկտների հայտնաբերման) ոլորտում տեղի ունեցավ հեղափոխական փոփոխություն՝ առաջարկվեց **YOLO (You Only Look Once)** ալգորիթմը:

- **Single Pass (Մեկ փուլով աշխատանք).** YOLO-ն առաջին One-Stage ալգորիթմն էր, որը միաժամանակ իրականացնում է և՛ օբյեկտի տեղադրության (localization), և՛ կլասիֆիկացիայի (classification) կանխատեսումը՝ մեկ forward pass-ի ընթացքում:
    
- **Region Proposals-ից Հրաժարում.** Այլևս չկա Region Proposal Network (RPN) կամ Selective Search: Մոդելը նկարից առանձին տիրույթներ չի առանձնացնում հետագա մշակման համար:
    
- **Միասնական Ռեգրեսիայի Խնդիր.** Նկարի պիքսելներից անմիջապես կանխատեսվում են Bounding Box-երը և կլասների հավանականությունները:
    
- **Real-time Արագություն.** Forward pass-ի պարզության շնորհիվ աշխատանքի արագությունը հասնում է **45 FPS-ից մինչև 150+ FPS** (կադր/վայրկյանում): Դա ապահովում է իրական ժամանակում (Real-time) աշխատանք, ինչը Two-Stage մոդելների դեպքում անհնար էր:
    
![[Pasted image 20260804162023.png]]
## One-Stage vs Two-Stage Object Detection Համեմատություն
![[Pasted image 20260804164715.png]]
### Two-Stage Detectors (օր.՝ R-CNN, Fast R-CNN, Faster R-CNN)

```
[Input Image] ──► [Backbone Network] ──► [Region Proposal] ──► [Classification & Localization] ──► Output
```

1. **Stage 1 (Region Proposal):** Input նկարը փոխանցվում է Backbone Network-ին (CNN կամ Transformer-based), որից հետո Region Proposal փուլում գտնվում են հավանական օբյեկտ պարունակող տիրույթները:
    
2. **Stage 2 (Classification & Regression):** Առաջարկված region-ների վրա Feature Map-ից կատարվում է feature extraction/pooling, ապա առանձին հաշվարկվում են Classification-ը և Bounding Box Regression-ը:
    
- **Թերություն.** Դանդաղ է, քանի որ պահանջում է երկու հաջորդական, ծանր փուլեր:
    

### One-Stage Detectors (օր.՝ YOLO)

```
[Input Image] ──► [Backbone Network] ──► [Head Network (Classification + Regression)] ──► Output
```

1. **Միասնական Ճարտարապետություն.** Input նկարն անցնում է Backbone Network-ով, որին հաջորդում է Head Network-ը:
    
2. **Միաժամանակյա Կանխատեսում.** Head Network-ը Feature Map-ի վրա միաժամանակ (simultaneously) կանխատեսում է և՛ կլասիֆիկացիան, և՛ bounding box-երի coordinates regression-ը:
    
- **Առավելություն.** Անհամեմատ արագ է, թեթև և հարմար Real-time համակարգերի համար:
    

## YOLO-ի Աշխատանքի Հիմնական Սկզբունքը (How YOLO Sees the World)
![[Pasted image 20260804165117.png]]
### 1. Grid Division (Ցանցի Բաժանում)

YOLO-ն մուտքային նկարը բաժանում է $S \times S$ չափսի ցանցի (Grid):

- Օրինակ՝ $13 \times 13$ կամ բնօրինակ հոդվածում $7 \times 7$:
    

### 2. The Golden Rule (Ոսկե Կանոնը)

> Եթե օբյեկտի **կենտրոնական կետը (center)** ընկնում է կոնկրետ Grid Cell-ի (բջջի) մեջ, ապա **միայն ու միայն այդ specific cell-ն է պատասխանատու** տվյալ օբյեկտը հայտնաբերելու համար:

- **Գործնական Օրինակ.** Ենթադրենք նկարում պատկերված է շուն: Շան Bounding Box-ը մեծ է և տարածվում է 3-րդ, 4-րդ, 6-րդ և 7-րդ Cell-երի վրա: Սակայն Bounding Box-ի ճշգրիտ կենտրոնական կետը գտնվում է 3-րդ Cell-ում:
    
- **Արդյունք.** Միայն 3-րդ Cell-ն է պատասխանատու այդ շանը գտնելու համար: 6-րդ Cell-ը ոչ մի պատասխանատվություն չունի և արհամարհում է այդ օբյեկտը:
    

### 3. Cell-ի Միաժամանակյա Կանխատեսում

Յուրաքանչյուր Cell միաժամանակ կանխատեսում է $B$ հատ Bounding Box-եր, դրանց Objectness Score-երը և կլասների հավանականությունները:

## Anchor Boxes (Priors) և Ռեգրեսիայի Տրամաբանությունը

### Ինչո՞ւ են անհրաժեշտ Anchor Box-երը

Եթե նեյրոնային ցանցին ստիպենք զրոյից կանխատեսել Bounding Box-ի չափսերն ու կոորդինատները ($x, y, w, h$), training-ի պրոցեսը կլինի ծայրահեղ **ոչ ստաբիլ (unstable)**: Ցանցը կարող է կանխատեսել բացասական թվեր կամ նկարի չափսերից անհամեմատ մեծ/փոքր արժեքներ:

Իրական դատասեթերում Bounding Box-երն ունեն որոշակի ստանդարտ, հաճախ հանդիպող ձևեր (Aspect Ratios).

- **Մարդիկ.** Ուղղահայաց, բարակ ուղղանկյուններ ($2:1$ կամ $3:1$):
    
- **Մեքենաներ/Սեղաններ.** Հորիզոնական, լայն ուղղանկյուններ ($1:2$):
    
- **Աթոռներ/Դեմքեր.** Քառակուսուն մոտ ձևեր ($1:1$):
    

### Anchor Box-երի Գտնումը (Clustering)
![[Pasted image 20260804165219.png]]
Զրոյից կանխատեսելու փոխարեն, նախապես սահմանվում են ստանդարտ ձևեր, որոնք կոչվում են **Anchor Boxes (Priors)**:

1. Վերցվում են դատասեթի բոլոր Ground Truth Bounding Box-երը:
    
2. Դրանց չափսերի վրա կատարվում է **Clustering (K-Means)**:
    
3. Ալգորիթմն առանձնացնում է $B$ հատ ամենահաճախ հանդիպող չափսեր (օրինակ՝ $B=3$ կամ $B=5$):
    

### Offsets-ի Կանխատեսում ($\Delta x, \Delta y, \Delta w, \Delta h$)

YOLO-ն չի կանխատեսում Bounding Box-ը զրոյից: Այն կանխատեսում է **Offsets (շեղումներ)** նախապես իմացած Anchor Box-երից.

$$\Delta = (\Delta x, \Delta y, \Delta w, \Delta h)$$

- **$\Delta x, \Delta y$:** Cell-ի կենտրոնից Bounding Box-ի կենտրոնի տեղաշարժը (offset):
    
- **$\Delta w, \Delta h$:** Anchor Box-ի լայնության ($w$) և բարձրության ($h$) մասշտաբավորումը (scaling factor):
    

> **Տրամաբանություն.** Մոդելին տրվում է լավ սկզբնական կետ (Anchor Box): Մոդելը միայն կանխատեսում է, թե որքանով է իրական օբյեկտը տարբերվում այդ ստանդարտ Anchor Box-ից: Սա թրեյնինգը դարձնում է կայուն և արագ համամիտվող (convergent):

## YOLO Output Tensor-ի Մաթեմատիկական Կառուցվածքը

YOLO-ի վերջնական Layer-ի ելքը (Output) 3D Tensor է՝

$$\text{Output Tensor Size} = S \times S \times (B \times 5 + C)$$

```
                         Output Tensor
              ┌──────────────────────────────────┐
              │           S × S Grid             │
              │  ┌────────────────────────────┐  │
              │  │ Cell (i, j)                │  │
              │  │  ├─ Anchor Box 1 (5 params)│  │
              │  │  ├─ Anchor Box 2 (5 params)│  │
              │  │  ├─ ...                    │  │
              │  │  ├─ Anchor Box B (5 params)│  │
              │  │  └─ Class Probabilities (C)│  │
              │  └────────────────────────────┘  │
              └──────────────────────────────────┘
```

### Output Tensor-ի Բաղադրիչները

- **$S \times S$:** Grid-ի չափսը (օր.՝ $13 \times 13$):
    
- **$B$:** Ամեն Cell-ի համար Anchor Box-երի քանակը (օր.՝ $B = 3$):
    
- **$5$:** Յուրաքանչյուր Anchor Box-ի համար կանխատեսվող 5 պարամետրերը.
    
    1. $\Delta x$: Կենտրոնի x շեղումը Cell-ի կենտրոնից:
        
    2. $\Delta y$: Կենտրոնի y շեղումը Cell-ի կենտրոնից:
        
    3. $\Delta w$: Լայնության մասշտաբավորման գործակիցը:
        
    4. $\Delta h$: Բարձրության մասշտաբավորման գործակիցը:
        
    5. **Objectness Score (Confidence):** Հավանականությունը ($0$-ից $1$), թե արդյոք տվյալ Box-ում **ընդհանրապես որևէ օբյեկտ կա**:
        
- **$C$:** Դատասեթի Կլասների քանակը (օրինակ՝ COCO Dataset-ի համար $C = 80$):
    

## Output Tensor-ի Աշխատանքը Գործնական Սցենարներում

### Սցենար 1: Cell-ում ԿԱ օբյեկտ ($Objectness Score \approx 1$)

- Մոդելն օպտիմիզացնում է $\Delta x, \Delta y, \Delta w, \Delta h$ արժեքները՝ Bounding Box-ը ճշգրիտ տեղադրելու համար:
    
- $C$ չափանի վեկտորը ցույց է տալիս կլասների հավանականությունները:
    
    - _Օրինակ._ $[Dog: 0.75, Bicycle: 0.20, Car: 0.05]$:
        

### Սցենար 2: Cell-ում ՉԿԱ օբյեկտ ($Objectness Score \approx 0$)

- Եթե Cell-ում որևէ օբյեկտի կենտրոն չկա, Objectness Score-ը դառնում է $0$:
    
- $C$ չափանի վեկտորը կարող է պարունակել պատահական թվեր, սակայն Loss function-ի հաշվարկման ժամանակ այդ կլասների հավանականությունները **արհամարհվում են**, քանի որ $Objectness Score = 0$ է:
    
- Սա թույլ է տալիս, որ Output Tensor-ի չափսը մնա ֆիքսված ($S \times S \times (B \times 5 + C)$), բայց ֆոնային (background) պատկերները աղմուկ չավելացնեն Loss-ի մեջ:

## 1. Non-Maximum Suppression (NMS)

### Խնդիրը (The Problem)

YOLO-ն նկարը բաժանում է grid-երի և կանխատեսում է հազարավոր Bounding Box-եր: Երբ նկարում առկա է մեծ օբյեկտ (օրինակ՝ մեքենա), այն զբաղեցնում է բազմաթիվ հարևան grid cell-եր: Արդյունքում, այդ հարևան cell-երից յուրաքանչյուրը կանխատեսում է իր Bounding Box-ը, ինչի հետևանքով նույն օբյեկտի համար ստանում ենք իրար վրա ընկած (overlapping) 4–5 կամ ավելի Bounding Box-եր:
![[Pasted image 20260804195150.png]]
### Լուծումը (The NMS Algorithm Step-by-Step)

NMS-ի նպատակն է ջնջել դուպլիկատ box-երը և թողնել միայն ամենահավաստին:

1. **Confidence Filtering**: Հեռացվում են բոլոր Bounding Box-երը, որոնց Objectness Confidence Score-ը փոքր է $0.5$-ից ($50\%$):
    
2. **Select Best Box**: Մնացած box-երից ընտրվում է ամենաբարձր Confidence Score ունեցող Bounding Box-ը:
    
3. **Calculate IoU Overlap**: Հաշվարկվում է այս ընտրված box-ի հատման մակերեսը (Intersection over Union — IoU) նույն class-ը կանխատեսող մյուս բոլոր box-երի հետ:
    
4. **Suppress Duplicates**: Եթե որևէ box-ի IoU-ն ընտրված box-ի հետ գերազանցում է սահմանված threshold-ը (օրինակ՝ $0.5$), դրանք համարվում են դուպլիկատներ և ջնջվում են (suppress):
    
5. **Repeat**: Գործընթացը կրկնվում է մնացած box-երի համար, քանի դեռ չմշակված box-եր կան:
    

_Նշում դասախոսությունից_: Դասական NMS-ը կտրուկ ջնջում է box-երը, սակայն գոյություն ունեն տարբերակներ (օրինակ՝ Soft-NMS կամ Box Averaging), որոնք box-երը ջնջելու փոխարեն դրանց score-ն են իջեցնում կամ կոմբինացնում են մի քանի box-եր՝ ստանալով ավելի ճշգրիտ նոր Bounding Box:

## 2. YOLO Loss Function

YOLO-ն մեկ unified network-ով միաժամանակ կանխատեսում է Bounding Box-ի կոորդինատները, Confidence score-ը և Class probability-ները: Սովորական Cross-Entropy-ն չի կարող օգտագործվել Bounding Box-ի կոորդինատների ռեգրեսիայի համար, դրա համար YOLO-ն օգտագործում է **Sum of Squared Errors (SSE)**:

### Responsibility Mechanism (Պատասխանատվության սկզբունքը)

Loss-ի որոշ մասեր ակտիվանում (ON) կամ անջատվում (OFF) են՝ կախված նրանից, թե տվյալ grid cell-ը **"Responsible"** է, թեոչ: Cell-ը համարվում է "Responsible", եթե ground truth օբյեկտի **կենտրոնը (center)** ընկած է հենց այդ cell-ի ներսում:

```
+------------------------------------------------------------------------+
| Total Loss = Box Loss + Object Conf Loss + Background Conf Loss + Class Loss |
+------------------------------------------------------------------------+
```

### Component 1: Bounding Box Loss

Հաշվարկվում է **ՄԻԱՅՆ Responsible** box-երի համար:

- **Center Error (Կենտրոնի սխալանք)**:
    
    $$(x_{pred} - x_{true})^2 + (y_{pred} - y_{true})^2$$
    
- **Size Error (Չափսերի սխալանք)**:
    
    $$(\sqrt{w_{pred}} - \sqrt{w_{true}})^2 + (\sqrt{h_{pred}} - \sqrt{h_{true}})^2$$
    
- **The Square Root Trick (Արմատի հնարքը)**:
    
    Ինչո՞ւ ենք վերցնում լայնության ($w$) և բարձրության ($h$) քառակուսի արմատը:
    
    - $10$ պիքսելի սխալը շատ փոքր օբյեկտի համար (օրինակ՝ հեռվում գտնվող թռչուն) հսկայական սխալ է:
        
    - $10$ պիքսելի սխալը մեծ օբյեկտի համար (օրինակ՝ մոտիկ կանգնած ավտոբուս) գրեթե աննշան է:
        
    - Քառակուսի արմատ հանելով՝ մաթեմատիկորեն փոքր box-երի չափսերի սխալներին ավելի մեծ կշիռ է տրվում loss function-ի մեջ:
        

### Component 2: Confidence Loss (When Object IS Present)

Հաշվարկվում է **Responsible Cell**-ում:

- Ground truth confidence-ը պետք է լինի $1.0$ (կամ իրական IoU-ն):
    
- $$\text{Loss} = (C_{pred} - 1.0)^2$$
    
- Խիստ պատժում է մոդելին, եթե օբյեկտը կա, բայց մոդելի confidence score-ը ցածր է:
    

### Component 3: Confidence Loss (When NO Object IS Present)

Հաշվարկվում է **Background Cells**-ում (որտեղ օբյեկտ չկա):

- Ground truth confidence-ը $0.0$ է:
    
- $$\text{Loss} = (C_{pred} - 0.0)^2$$
    
- **The Imbalance Fix ($\lambda_{noobj}$)**: Նկարի ~90%-ը դատարկ background է: Եթե այս loss-ը թողնենք նույն ուժգնությամբ, այն կճնշի մոդելին, և մոդելը սովորելու է ամեն ինչի համար կանխատեսել $0$ confidence: Ուստի YOLO-ն background confidence loss-ը բազմապատկում է $\lambda_{noobj} = 0.5$ գործակցով, որպեսզի թուլացնի դրա ազդեցությունը:
    

### Component 4: Classification Loss

Հաշվարկվում է **ՄԻԱՅՆ Responsible Cell**-երում:

- Հաշվում է կանխատեսված class probability-ի և իրական probability-ի ($1.0$ թիրախային class-ի համար, $0.0$ մնացածի) քառակուսային տարբերությունը:
    
- **Կարևոր**: Եթե cell-ում օբյեկտ չկա, YOLO-ն ամբողջությամբ ԻԳՆՈՐ Է ԱՆՈՒՄ class prediction-ները (զրոյական պատիժ):
    

### Վերջնական Loss Բանաձևը

$$\text{Total Loss} = \lambda_{coord} \sum_{\text{responsible}} \text{Box Loss} + \sum_{\text{obj}} (C_{pred} - 1)^2 + \lambda_{noobj} \sum_{\text{noobj}} (C_{pred} - 0)^2 + \sum_{\text{responsible}} \text{Class Loss}$$

## 3. Single Shot MultiBox Detector (SSD)

### YOLO v1-ի Թուլությունը

YOLO v1-ը դժվարանում էր գտնել շատ փոքր օբյեկտներ, որովհետև $13 \times 13$ (կամ $7 \times 7$) grid-ը չափազանց կոպիտ (coarse) էր փոքր detail-ներ ֆիքսելու համար:

### SSD-ի Ինովացիան (Multi-Scale Architecture)

SSD-ն կանխատեսումներ է անում ցանցի **տարբեր խորությունների վրա գտնվող multiple feature map-երից**:

```
Input Image 
   │
   ▼
[CONV Layers] ───► Feature Map (38x38) ───► Detects Tiny Objects
   │
   ▼
[CONV Layers] ───► Feature Map (19x19) ───► Detects Medium Objects
   │
   ▼
[CONV Layers] ───► Feature Map (5x5)   ───► Detects Large Objects
```

|**Feature Map Size**|**Receptive Field**|**Օբյեկտների չափսը**|
|---|---|---|
|**Մեծ Feature Maps (օր. $38 \times 38$)**|Փոքր receptive field|Փոքր / մանր օբյեկտներ|
|**Փոքր Feature Maps (օր. $5 \times 5$)**|Մեծ receptive field (ամբողջ նկարը)|Մեծ / խոշոր օբյեկտներ|

_Ժամանակակից YOLO-ները (YOLOv2-ից սկսած)_ ներառել են SSD-ի այս multi-scale տրամաբանությունը (Feature Pyramid Networks / Anchor boxes):

## 4. Evaluation Metrics (Գնահատման Մետրիկաներ)

### Intersection over Union (IoU) / Jaccard Index

Աշխարհագրական/տարածական Bounding Box-երի ճշտությունը չափելու համար սովորական accuracy-ն չի աշխատում: Օգտագործվում է IoU.

$$\text{IoU} = \frac{\text{Area of Overlap}}{\text{Area of Union}}$$

```
  Ground Truth        Predicted
  +---------+        +---------+
  |         |        |         |
  |    +----+----+   |    +----+----+
  |    |////|    |   |    |    |    |
  +----+----+    |   +----+----+    |
       |         |        |         |
       +---------+        +---------+
     Area of Overlap     Area of Union
```

- **Thresholding**: Կանխատեսումը համարվում է **True Positive (TP)**, եթե $\text{IoU} > 0.5$ (կամ այլ սահմանված threshold) **ԵՎ** class label-ը ճիշտ է:
    

### Precision, Recall, AP և mAP

```
+-----------------------------------------------------------------------+
| Precision = True Positives / Total Predicted Boxes                      |
| Recall    = True Positives / Total Ground Truth Objects                 |
+------------------------֊֊---------------------------------------------+
```

- **Precision**: Բոլոր կանխատեսված box-երից քանի՞սն էին իրականում ճիշտ:
    
- **Recall**: Բոլոր իրական (ground truth) օբյեկտներից քանի՞սը հաջողվեց գտնել:
    
- **Average Precision (AP)**: Ֆիքսված մեկ class-ի (օրինակ՝ "Dog") Precision-Recall կորի (P-R Curve) տակի մակերեսն է (Area Under Curve):
    
- **Mean Average Precision (mAP)**: Բոլոր class-երի AP-ների միջին թվաբանականն է:
    
    - **$\text{mAP}@0.5$**: Հաշվարկվում է ֆիքսված $\text{IoU} = 0.5$ threshold-ի դեպքում:
        
    - **$\text{mAP}@0.5:0.95$**: Հաշվարկվում է IoU threshold-ը $0.50$-ից մինչև $0.95$ փոփոխելով ($0.05$ քայլով) և դրանց միջինը վերցնելով:
        

```
Precision
  1.0 ┼───┐ (conf-thresh 0.9: P=0.98, R=0.3)
      │   └───┐
  0.5 │       └──────┐
      │              └───────────┐ (conf-thresh 0.1: P=0.2, R=0.9)
  0.0 ┴───────────────────────────┴
      0.0             0.5        1.0  Recall
```

## 5. Efficient Architectures & Edge Deployment

### Խնդիրը (The Deployment Problem)

Չնայած YOLO-ն արագ է, CNN-ները հեռախոսների կամ դրոնների (edge devices) վրա աշխատեցնելը մաթեմատիկորեն ծանր է:

- Ստանդարտ ResNet-50-ը պահանջում է միլիարդավոր **FLOPs (Floating-point operations)** մեկ նկարի համար:
    
- Ստանդարտ convolution-ը միաժամանակ կատարում է spatial filtering (Height/Width) և channel mixing (RGB/Features):
    
- Հաշվարկման ծախսը բազմապատկական է՝ $\text{Kernel} \times \text{Kernel} \times \text{Input Channels} \times \text{Output Channels}$:
    

### Depthwise Separable Convolutions

Լուծումը ստանդարտ convolution-ը երկու առանձին, ավելի էժան քայլերի բաժանելն է:

```
[Standard Convolution]  ===>  [Depthwise Conv]   +   [Pointwise Conv]
(Spatial + Channel)           (Spatial Only)         (Channel Only)
                              (k x k per channel)    (1 x 1 across channels)
```

1. **Step 1: Depthwise Convolution**:
    
    Կիրառվում է $k \times k$ ֆիլտր **յուրաքանչյուր channel-ի վրա առանձին**: Կատարվում է միայն spatial filtering:
    
2. **Step 2: Pointwise Convolution**:
    
    Կիրառվում է $1 \times 1$ convolution բոլոր channel-ների վրայով: Կատարվում է միայն channel mixing:
    

### Արդյունքը (Impact)

$3 \times 3$ kernel-ի դեպքում Depthwise Separable Convolution-ը կրճատում է հաշվարկների քանակը մոտ **8-ից 9 անգամ**՝ գրեթե առանց accuracy-ի կորստի: Սա հնարավոր է դարձնում **MobileNet** և **YOLO-Lite** մոդելների աշխատանքը հեռախոսների և դրոնների վրա:
